========================================================================
 RANDOM QUESTION BOT — YAGPDB setup  (the generic /topic command)
========================================================================

WHAT THIS DOES
  Stores 350 general conversation questions as ONE database entry (a cslice
  under the key "questions"), then a tiny command walks through them
  top-to-bottom in order. Storing the list in the DB sidesteps the
  10,000-char-per-custom-command limit; walking with a persisted counter
  (instead of picking at random) means no question repeats until the whole
  list has been shown.

  This is the GENERIC topic list. The RP / OC / worldbuilding bots in
  ../rp_topics/, ../oc_topics/, ../wb_topics/ use the SAME mechanism under
  their own keys ("rpquestions", "ocquestions", "wbquestions"), so the lists
  never mix and any one can be reseeded without touching the others.

WHY THIS APPROACH (free-tier math)
  - CC code cap ........... 10,000 chars per command -> the full ~22 kB list
                            can't fit in one command, so the seeder is split
                            into 3 chunks (~6.7 / 8.0 / 7.4 kB each).
  - DB entry COUNT cap .... 50 x member_count (free)  -> we use 2 keys: the
                            list ("questions") + a tiny walk counter
                            ("questions_idx").
  - DB entry SIZE cap ..... 100 kB per entry          -> our list is ~22 kB.
  - DB calls per exec ..... 10 (free)                 -> picker uses just 2.
  Net permanent cost: 1 custom command + 2 database entries.

------------------------------------------------------------------------
 FILES
------------------------------------------------------------------------
  seeder_chunk_1.txt .. RESETS "questions", loads questions 1-117, and resets
                        the walk counter to the top.
  seeder_chunk_2.txt .. APPENDS questions 118-234.
  seeder_chunk_3.txt .. APPENDS questions 235-350.
  asker.txt ........... the permanent picker (350 questions total).

------------------------------------------------------------------------
 STEP 1 — SEED THE DATABASE (one time)
------------------------------------------------------------------------
  You only need ONE spare command slot. Reuse it 3 times:

  1. Create a new Custom Command.
       Trigger type: Command
       Trigger:      -seed          (temporary; anything works)
  2. Paste the contents of seeder_chunk_1.txt as the response. Save.
  3. Run  -seed  in your server. It replies:
       "Reset "questions" (walk reset to the top) and loaded chunk 1/3. Total now: 117".
  4. Edit the SAME command: replace the response with seeder_chunk_2.txt.
     Save, run -seed again -> "Loaded chunk 2/3. Total now: 234".
  5. Replace with seeder_chunk_3.txt. Save, run -seed ->
       "Loaded chunk 3/3. Total now: 350".
  6. DELETE the -seed command. The data stays in the database.

  RE-RUNNABLE AS A SET: chunk 1 wipes the key before loading, so if you lose
  track just start over from chunk 1 in order — you always end up with exactly
  350, never duplicates. (Running a single APPEND chunk twice WILL duplicate,
  so run each chunk once per pass.)

------------------------------------------------------------------------
 STEP 2 — CREATE THE ASKER (permanent)
------------------------------------------------------------------------
  Create a new Custom Command and paste asker.txt as the response.

  Pick ONE trigger:
   * On demand:   Trigger type = Command,  Trigger = topic
                  -> users type  -topic  for the next question in the list.
   * Automatic:   Trigger type = Interval,  every N minutes/hours,
                  set the target channel -> bot posts one on its own.
                  (Free tier minimum interval is ~5-10 min.)

------------------------------------------------------------------------
 STEP 3 — IF YOUR TRIGGER IS "topic" (override the built-in command)
------------------------------------------------------------------------
  YAGPDB ships a built-in "topic" command (Fun group). If you name this
  custom command's trigger "topic", BOTH fire on -topic and you get two
  replies. Built-in commands and custom commands are separate systems on
  the same prefix, so you must disable the built-in one:

  1. Dashboard -> Core -> Command Settings.
  2. Find the built-in "topic" command (Fun group).
  3. Disable it (or add an override that disables just "topic"). Save.

  Command Settings only governs BUILT-IN commands -- it never touches
  custom commands, so your picker keeps working and -topic now runs only
  yours.

  DON'T uncheck the global "All commands enabled" to do this -- that kills
  every built-in command. Disable the single "topic" command only.

  (Not using the name "topic"? Skip this step -- no other trigger, e.g.
  "question"/"q"/"ask", collides with a built-in.)

------------------------------------------------------------------------
 HOW THE PICKER WORKS (asker.txt)
------------------------------------------------------------------------
  {{ $q := (dbGet 0 "questions").Value }}
  {{ $c := toInt (dbIncr 0 "questions_idx" 1) }}
  {{ $i := toInt (mod (sub $c 1) (len $q)) }}
  {{ index $q $i }}

  - dbGet 0 "questions"          reads the single stored cslice (1 DB op).
  - dbIncr 0 "questions_idx" 1   atomically bumps a persisted counter and returns
                                 its NEW value (1, 2, 3, ...) — 1 DB op.
  - sub $c 1                     turns that into a 0-based position for THIS call.
  - mod ... (len $q)             wraps back to the top after the last question.
  - toInt ...                    REQUIRED: YAGPDB math returns a float64, and
                                 `index` refuses a float — this casts it to int.
  - index $q $i                  pulls that question out.

  Because the counter only moves forward by 1, every question is shown once
  before any repeats — no more random duplicates. Chunk 1 of the seeder resets
  the counter to 0, so a reseed also restarts the walk from the top.

------------------------------------------------------------------------
 ADDING / EDITING QUESTIONS LATER
------------------------------------------------------------------------
  Easiest: edit the backtick lines across the chunk files (keeping each chunk
  under 10,000 chars), then re-run chunks 1 -> 2 -> 3 once in order. Chunk 1
  resets both the list and the walk counter, so the new list fully replaces the
  old and starts again from the top.

  To append a few without re-listing everything, make a one-off command:
    {{ $s := (dbGet 0 "questions").Value }}
    {{ $s = $s.AppendSlice (cslice `New question one?` `New question two?`) }}
    {{ dbSet 0 "questions" $s }}
    Total now: {{ len $s }}

  To wipe entirely:  {{ dbDel 0 "questions" }}{{ dbDel 0 "questions_idx" }}
========================================================================
