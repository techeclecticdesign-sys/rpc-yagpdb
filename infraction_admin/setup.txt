INFRACTION ADMIN COMMAND — SETUP
================================

WHAT THIS IS
------------
One staff prefix command, -infractions, that manages the advert-infraction
counter the advert commands maintain (the per-user `infractionLog` records +
`infractionDates` legacy list + `advertBan` flag). You pick an action, a user,
and (depending on the action) an index or a reason:

  -infractions view  @member            → count + numbered list + ban status
  -infractions @member                  → alias for view
  -infractions clear @member            → wipe history AND lift ban
  -infractions drop  @member <index>    → drop ONE record by its list number
  -infractions add   @member <reason>   → add a hand-written infraction

(`-` is a stand-in for whatever command prefix your server uses.)

"view" shows how many infractions the member has in the last 6 months, then one
NUMBERED line per infraction: its index, the date, what it was for (e.g.
"headers, banned word" — a post with several problems is one line with a
comma-joined reason), and a jump-link to the offending post when one was
recorded and still exists. Older entries from before this feature, and
hand-added ones, show without a jump-link; hand-added ones show their reason.

"drop" removes a single record by the NUMBER shown in "view" — run view first,
then drop that index. If dropping takes the member under 4 infractions, any
active advert ban is lifted. Dropping never re-applies or extends a ban.

"add" appends a fresh infraction dated now with a staff-written reason. The
reason is the rest of the line, so it may be several words — no quotes needed.
If the member reaches 4+ infractions, they are advert-banned for 14 days
immediately (this is also how you apply a ban by hand). Any pings in the reason
(@everyone, @here, user/role mentions) are neutralised before it is stored, so
they cannot ping here or when the reason is later re-shown by "view".

"clear" wipes the whole history and lifts the ban — use it to zero someone out.

Note on the counter: from the 4th infraction on, every further infraction
(re)applies a fresh 14-day ban. "drop"/"clear"/"add" only ever change history +
the ban as described above; nothing is auto-dropped on the 4th infraction.


CREATE THE COMMAND
------------------
  1. Dashboard → Custom Commands → Create New.
  2. Trigger type:  Command.
  3. Trigger (name), lowercase:  infractions
  4. Response: paste infractions.go.
  5. Make sure the command is ENABLED, then Save.

There are NO options/arguments to define in the dashboard — the code parses the
words after the command itself (.CmdArgs): the action, the @member, and then the
index (for drop) or the reason (for add). There are also no channel/role IDs to
fill in: it reads/writes the same database the advert commands use, keyed by the
mentioned user.


RESTRICT TO STAFF  (IMPORTANT)
------------------------------
This edits moderation state, so lock it down IN THE COMMAND'S OWN SETTINGS
(a prefix command has no Discord integration gate — that only exists for slash
commands):
  • Custom Command → "Require roles" — add your staff role(s) so only they can
    run it. Without this, anyone can run it.
  • Optionally also restrict it to a staff-only channel (Custom Command →
    channel restrictions). That channel then doubles as your audit log, since
    Discord shows who sent each command.


VISIBILITY
----------
Prefix commands always reply visibly in-channel (they can't be ephemeral), so
restrict the command to a staff-only channel and every view/clear/drop/add — and
who ran it — is recorded there.
